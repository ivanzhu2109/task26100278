# autoscaler

离线自动扩容决策库（Go），由托管平台直接调用。配置、指标与扩容记录全部保存在进程内存中，不依赖任何外部服务。

## 规则

- 每个部署初始运行并分配 2 vCPU；持续时长在初始化时一次给定（60–900 秒整数），之后不修改。
- CPU 严格大于 80% 算高位；连续高位满足持续时长后每次扩容 +2 vCPU；同一部署两次扩容至少间隔 600 秒，首次扩容无冷却限制。
- 指标自时间戳起有效，直到下一条指标到来或经过 300 秒（以先发生者为准，不含失效时刻）；失效、降至 80% 及以下、部署停止都会清零连续高位时长。
- 停止不回收 vCPU、不清除上次扩容时间；恢复运行后只能使用时间戳不早于恢复时刻的指标。
- 同一时刻的处理顺序：运行状态变化 → 新指标 → 指标失效 → 扩容判断；恰在旧指标失效时收到新指标视为连续覆盖。
- 扩容发生在持续时长满足、冷却结束且仍处于有效高位的最早整数秒，不必等待下一条指标；扩容不清空连续高位时长。

## 接口

```go
e, err := autoscaler.NewEngine([]autoscaler.Config{
    {DeploymentID: "shop-1", Duration: 120},
})

// 1. 提交一批带时间戳的 CPU 指标或运行状态变化（允许乱序、重复）
e.Submit([]autoscaler.Input{
    {DeploymentID: "shop-1", Timestamp: 0, CPU: ptr(91.5)},
    {DeploymentID: "shop-1", Timestamp: 100, Running: ptr(false)},
})

// 2. 推进确认水位（只进不退；不大于水位的迟到输入被忽略）
e.AdvanceWatermark(1000)

// 3. 查询当前 vCPU 与已确认扩容记录（只包含水位以内的结果）
snap, ok := e.Query("shop-1")
```
